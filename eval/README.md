# 评测与数据治理（内建在 agent 项目里）

这个目录回答三个具体问题，每个问题都由代码逼着回答，而不是写在文档里：

1. **这份结果用的是哪份数据？** —— 语料用内容哈希做版本身份（不是"v1""v2"这种自报编号），
   评测运行与数据版本之间留血缘边，能反查到具体哪几道题。
2. **差异是真的还是噪声？** —— 同一批 case 上的两个臂是**配对**的，所以用 McNemar 精确检验，
   不看"两个比率谁大"。n=16 时这一条尤其关键。
3. **这一版能不能发？** —— 三类门禁：通过率下限、相对基线不得显著回归、结论前必须调用工具。
   未通过一律退出码 1，可以直接当 CI 步骤。

## 为什么它在这个仓库里，而不是另一个仓库

评测治理是**这个项目的一部分**，不是外部工具：谁定义扰动任务、谁判"答对"、谁能说"这版不能发"，
都必须在同一个仓库里，否则报告和门禁会各自演化。

底层的数据登记、报告入库、配对统计、门禁与审计由一个零第三方依赖的内部库
[`maldi-ms-platform`](https://github.com/Wang-13137/maldi-ms-platform) 提供；本目录是它在
agent 项目里的**唯一入口**。CI 做的事和本地做的事完全一样：

```bash
# 本地：平台放在同级目录即可
python eval/governance.py --out reports/governance.json

# 平台在别处时用环境变量指过去
MALDI_PLATFORM_SRC=/path/to/maldi-ms-platform/src python eval/governance.py
```

退出码：`0` 全部符合预期｜`1` 有断言不成立（结论或门禁行为变了）｜`2` 环境或产物校验失败。

## 目录

| 路径 | 作用 |
|---|---|
| `corpus/cases.json` | 16 条评测用例（基线 / 无信号 / 批次 / 诱饵 × 4 seed），内容哈希的锚点 |
| `released/agent_glm4flash_64_v1.json` | 冻结的真实报告：glm-4-flash，4 臂 × 16 条 = 64 条 |
| `released/manifest.json` | 上述两个产物的 sha256。被改一个字节，流水线拒绝启动（退出码 2） |
| `policy.json` | 门禁策略：基线臂、候选臂、alpha、通过率下限、必须调用的工具 |
| `.gitattributes`（仓库根） | 把上面几个文件锁成 `eol=lf`：参与哈希的文件换行符一变，身份就变了 |
| `governance.py` | 流水线本体：登记 → 入库 → 配对比较 → 三类门禁 → 审计 → 出报告 |

## 流水线跑出来的东西（本地与 CI 一致）

```
A_full           11/16  rate=0.6875
B_no_warning     11/16  rate=0.6875
C_no_tool        0/16   rate=0.0000
D_loose_prompt   11/16  rate=0.6875

配对比较 A_full vs C_no_tool：仅基线过=11 仅候选过=0 p=0.0009765625
```

同一份报告换台机器重跑，p 值不会变——这是"可复现"的最低要求。

## 它同时演示的四件事

1. **配对检验而不是比大小**：11/16 与 0/16 的差距，在配对 McNemar 下 p≈9.8e-4；
   若按两个独立比率做卡方，在小样本上会给出不同的（且更乐观的）结论。
2. **门禁有方向**：候选显著变差要拦（退出码 1），反过来（拿差的当基线）必须放行——
   只会说"不通过"的门禁，最后没人看。
3. **过程门禁与结果门禁分开**：C 组没调用置换检验，即使它的结论碰巧对，也该被拦。
4. **真实数据只出元数据**：`uti-urine-real37` 以 `classification=real` 登记，
   `payload` 导出在库层直接抛错，且这次"被拒"本身写进审计日志（只追加，库层禁止改删）。

## 一个必须记下来的坑：换行符会毁掉内容寻址

第一版在 Windows 上全部通过，推到 CI 直接退出码 2。原因：JSON 在 Windows 上是 CRLF，
git 存成 LF，按原始字节算 sha256 就是两个不同的身份——**本地绿、CI 红**。

现在两层保险：`.gitattributes` 把 `eval/released/*.json` 与 `eval/corpus/*.json` 锁成
`eol=lf`；校验函数按 LF 归一化（并处理 `\r` 恰好落在读块边界的情况）。测试里有一条
专门把同一份内容写成 CRLF 与 LF，断言两者哈希相等。

## 它**没有**做什么（写在前面，省得被问）

- 不做自动调参、不做模型选择：它只判"这次结论站不站得住"。
- 不替人解释业务：p 值只说明差异是否超出噪声，是否值得上线由人决定。
- 不收集真实受试者数据：仓库里只有合成扰动数据与报告，真实谱与特征矩阵始终留在本地。
- 不做分布式调度与多租户：单机、单文件 SQLite，够用就停。
